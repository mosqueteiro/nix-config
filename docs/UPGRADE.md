# Upgrade Guide

How to keep this NixOS configuration up-to-date and handle version transitions.

---

## Updating Pinned Dependencies (npins)

The entire dependency tree is pinned via `npins/sources.json`. Do not edit this file manually.

### Update all pins

```bash
npins update
```

### Update a specific pin

```bash
npins update nixpkgs
npins update den
npins update home-manager
```

### Add a new pin

```bash
# GitHub repository
npins add github owner repo

# NixOS channel
npins add channel nixpkgs-unstable
```

### Check what changed

```bash
# Show current pin revisions
npins show

# After update, review sources.json diff
git diff npins/sources.json
```

## Update Cadence

| Component | Recommended Cadence | Notes |
|-----------|--------------------|-------|
| `nixpkgs` (unstable) | Weekly | Track nixpkgs-unstable channel |
| `nixpkgs-stable` | Monthly | Aligns with nixos-25.11 patch releases |
| `den` | Per release | Check [den changelog](https://den.oeiuwq.com/releases/) first |
| `home-manager` | Weekly | Track master branch |
| `nixos-hardware` | Per hardware update | Track master branch |
| `nix-amd-ai` | As needed | For NPU/ROCm driver updates |

### General strategy

1. **Update nixpkgs first** — most packages come from here.
2. **Build and test** with `nixos-rebuild build --file . -A nixosConfigurations.frameworkDesktop`.
3. **Switch** with `sudo nixos-rebuild switch --file . -A nixosConfigurations.frameworkDesktop`.
4. **If boot fails**, select a previous generation from the systemd-boot menu.

## Upgrading den

den is a pinned dependency in `npins/sources.json`. Before updating:

1. Read the [den changelog](https://den.oeiuwq.com/releases/) for breaking changes.
2. Check if any aspect syntax or context variables have changed.
3. Update the pin:
   ```bash
   npins update den
   ```
4. Build and evaluate:
   ```bash
   nix eval --file . nixosConfigurations.frameworkDesktop.config.system.build.toplevel
   nixos-rebuild build --file . -A nixosConfigurations.frameworkDesktop
   ```

### Common den migration concerns

- **Aspect structure changes**: den may change how `includes`, `provides`, or `context` dispatch works.
- **Schema changes**: `den.schema.user.classes`, `den.default.*` may be renamed or restructured.
- **Removed options**: Options like `den.default.homeManager.stateVersion` may be replaced.

## State Version

`system.stateVersion` and `home.stateVersion` control NixOS/home-manager defaults for stateful data. Do not change these.

**Current state version:** 25.11

> [!WARNING]
> Once bumped, you cannot safely downgrade `stateVersion`. Stateful data (databases, file layouts, etc.) may assume the new format.

## Rolling Back

### Roll back a single switch

NixOS keeps previous generations in the systemd-boot menu. At boot, select an older generation.

### Roll back to a specific generation

```bash
# List generations
sudo nixos-rebuild list-generations

# Switch to a specific generation (by index)
sudo nixos-rebuild switch --rollback
```

### Roll back after a failed build

If a `nixos-rebuild switch` fails _before_ it finishes, your current generation is unaffected — it never became the default.

If it partially applied, reboot and select the previous generation from systemd-boot.

### Roll back npins pins

```bash
# Revert npins to previous state
git checkout HEAD~1 npins/sources.json

# Then rebuild
nixos-rebuild build --file . -A nixosConfigurations.frameworkDesktop
```

## Post-Update Checklist

After any significant update:

- [ ] Build succeeds: `nixos-rebuild build --file . -A nixosConfigurations.frameworkDesktop`
- [ ] System boots and reaches SDDM/Plasma
- [ ] GPU accel works: `rocm-smi` or `rocminfo`
- [ ] Ollama works: `ollama list`
- [ ] Bluetooth connects
- [ ] Sound works (PipeWire)
- [ ] Steam launches
- [ ] TPM unlock works (no passphrase prompt at boot)
- [ ] Browser (Brave) launches
- [ ] Wezterm launches

## Major Version Upgrades

When NixOS releases a new stable branch (e.g., 25.11 → 26.05):

1. **Update nixpkgs pin** to the new release channel.
2. **Update nixpkgs-stable** to the new release.
3. **Bump stateVersion** after the switch is confirmed working.
4. **Check the NixOS release manual** for breaking changes.
5. **Check home-manager release notes** for breaking changes.
6. **Check den changelog** for any framework changes needed.

### This repo tracks unstable

This repo primarily uses `nixpkgs-unstable` (currently nixpkgs-26.11pre), so there is no "release upgrade" — updates are continuous. However, `stateVersion` should still be bumped when the corresponding stable release is cut, as home-manager defaults follow the state version.
